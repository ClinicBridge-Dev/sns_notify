# Meta 수신함 확장 프로그램 — 수동 확인 목록

자동 테스트(`node --test extension/test/*.test.js`)는 순수 로직만 검증한다. 실제 Meta Business Suite 화면에서는
한 번도 실행하지 않았다. 아래 항목은 **전부 미확인**이며, 사용 전에 사람이 테스트 계정으로 확인한다.
확인한 결과는 이 문서가 아니라 기획서 3-6의 U 표에 기록한다.

공통 규칙: 전송이 일어나는 확인은 **테스트용 상대 계정과의 대화에서만** 한다. 실제 고객 대화를 열지 않는다.
선택자 문제는 `extension/content/selectors.js` 한 파일에서 고친다.

## (a) 사전 확인 U1–U12

| U | 확인할 것 | 가정이 있는 곳 | 결과에 따라 바꿀 것 |
|-|-|-|-|
| U1 | Instagram 목록 항목 구조, 발신자가 아이디인지 표시 이름인지, 채널 아이콘 alt | `content/selectors.js` `CHANNEL_ICON_ALTS`(예상값 `Instagram`), `lib/listcand.js` `parseItemLines`(3-3 줄 순서 가정) | alt가 다르면 `CHANNEL_ICON_ALTS` 수정. 줄 순서가 다르면 `parseItemLines` 수정 |
| U2 | `/latest/inbox/all`에 두 채널 대화가 함께 보이는지 | 가정 없음(채널 탭을 쓴다는 전제) | 기록만 |
| U3 | 탭을 30분 이상 가렸을 때 배지·목록이 계속 갱신되는지 | `content/watcher.js` 가려진 탭 처리, `lib/watchdog.js` | 갱신이 멈추면 기획서 6-6 운영 안내(탭을 보이게 둠)로 충분한지 확인하고 기록 |

| U5 | Instagram 화면 전송 버튼 aria-label | `content/selectors.js` `SUBMIT_LABELS`(`Submit`, 후보 `Send`), `submitButton()` | 실제 값을 `SUBMIT_LABELS`에 추가(한국어 UI면 한국어 값도) |
| U6 | 합성 붙여넣기로 Lexical 입력창을 바꿨을 때 Meta가 내용을 인식하는지 | `content/composer.js` `insertText`(1순위 paste, 2순위 `execCommand('insertText')`) | 둘 다 실패하면 R5·R6 입력창 교체 방식을 다시 설계해야 한다 |
| U7 | 번역 후 `submitButton().click()`으로 전송이 이어지는지 | `content/composer.js` 전송 이어가기(버튼 없을 때만 합성 Enter) | 안 되면 1.5초 뒤 "Enter를 한 번 더 눌러 전송하세요"가 나온다. 이것이 기본이 되면 옵션에 "Enter 두 번" 표시(기획서 8-5) |
| U8 | service worker에서 DeepL 호출이 CORS로 막히지 않는지 | `background.js` `TRANSLATE`, `CHECK_DEEPL_KEY` | 막히면 기획서 7-4의 중계 설정을 추가해야 한다(미구현). 옵션의 [키 확인]과 service worker 콘솔로 확인 |
| U9 | 한글 조합 중 Enter의 이벤트 순서(keydown 1회/2회, Meta가 전송하는 이벤트). macOS와 Windows 각각 | `content/composer.js` keydown/compositionend 처리, `lib/sendgate.js` | 두 순서 모두 처리하게 돼 있다. 글자 누락·이중 전송이 있으면 composer의 조합 처리 수정. keyup 전송이면 keyup 차단 확인 |
| U10 | 수신함 이동 중 주소에서 asset_id가 빠지는 순간, 다른 계정의 asset_id | `content/selectors.js` `assetIdFrom`(탭 링크 fallback), `content/watcher.js` | 빠지는 순간마다 20초 안정화로 들어간다. 너무 잦으면 안정화 조건 조정 |
| U11 | 검색·필터가 켜진 상태의 판별 방법, "읽지 않음으로 표시" 위치와 배지 변화 | `content/selectors.js` `filterState()`, `SEARCH_SELECTORS`, `isListOrThreadMenu()` | 판별이 안 되면 필터 영역 클릭을 화면 전환으로 보는 기획서 6-1 대체 동작이 아직 없다(알려진 한계). "읽지 않음으로 표시" 기능이 없으면 `userActionRecent`를 항상 false로 |
| U12 | (1) 탭 전환 때 배지 숫자가 잠깐 사라지는지 (2) 목록이 보이는 항목만 그리는지 (3) 가려진 탭에서 목록이 갱신되는지 (4) 목록 항목이 여러 단계로 바뀌는지 | `lib/constants.js` `DROP_WAIT_MS`(3000), `HIDDEN_TAB_DOUBLE_OBSERVE`(true), `content/selectors.js` `listScroller()` | (1) 사라지지 않으면 `DROP_WAIT_MS`를 0으로. (2) 스크롤 요소가 다르면 `listScroller()` 수정. (4) 단계 변화가 없으면 `HIDDEN_TAB_DOUBLE_OBSERVE`를 false로 |

추가로 먼저 볼 것: 정상 수신함 화면에 `input[type="password"]`나 captcha iframe이 **없는지**. 있으면 로그인 판별이
오탐해 감지가 조용히 멈춘다(`content/watcher.js` 로그인·체크포인트 판별).

## (b) 기능별 수동 확인

설치: `chrome://extensions` → 개발자 모드 → 「압축 해제된 확장 프로그램 로드」 → `extension/`. 오류 없이 로드되고
옵션 페이지가 열리는지, service worker 콘솔에서 `chrome.storage.local.get(null)`로 저장 구조가 보이는지 먼저 본다.

### 옵션 (R7, 설정)
- [ ] 빠른 메시지 3개 추가 → 브라우저 재시작 후 유지
- [ ] 내보내기 → 그 파일을 바꾸기로 가져오면 동일
- [ ] 깨진 JSON, 제목 누락 파일 → 항목별 이유가 보이고 기존 데이터 유지. 같은 파일을 다시 골라도 `change`가 뜨는지
- [ ] Webhook에 `https://example.com/x` → 저장 거부
- [ ] 저장 후 Webhook·DeepL 키가 가려져 보이고, `:fx` 경고, 숨은 패널 토글
- [ ] [현재 수신함을 알림 대상으로 지정]: 수신함 탭이 없으면 "수신함을 먼저 여세요", 계정 2개면 선택 목록
- [ ] 테스트 메시지가 Slack에 도착. 잘못된 Webhook이면 옵션 상태와 아이콘 `!`, 재시도 없음

### R1 Slack 알림
- [ ] Instagram, WhatsApp 각각: 신규 발신자, 기존 대화 추가 메시지 (보는 채널 / 다른 채널 탭)
- [ ] 같은 문구 반복, 10초 안에 연속 3건
- [ ] 내 답장에는 알림 없음
- [ ] 채널 탭 전환, 검색, 필터, 목록 스크롤(조금 내렸다 올림, 오래 내려 둠), 완료 처리, 나눠 그려지는 동안 오알림 없음
- [ ] 목록을 오래 내려 둔 사이 온 메시지가 맨 위 복귀 때 한 번 더 나가지 않음
- [ ] 배지 2에서 모두 읽고 10초 뒤 새 메시지 → 알림
- [ ] 탭 30분 이상 가림 후 수신(U3), 열어 둔 대화에 수신(U4)
- [ ] 네트워크 끊고 수신 → 복구 후 도착(알람 기반이라 최대 1분 정도 늦음)
- [ ] 탭 1개/2개(Instagram+WhatsApp) 조합: 보는 채널은 상세 알림 1건, 안 보는 채널은 "N건" 알림 또는 건수+보충 1건, "새 메시지"가 두 번 오지 않음, 연속 2건의 상세가 맞는 알림에 붙음
- [ ] 보류(5초) 중 service worker를 `chrome://serviceworker-internals`에서 중지 → 다음 신호나 알람 때 알림 도착
- [ ] 수신함 탭 2개 → 알림 1건. 감지 담당 탭을 닫고 바로 수신 → 다른 탭이 이어받아 도착. SW 재시작 후 `ownerTabId` 유지
- [ ] 모든 수신함 탭을 닫음 → 3~4분 안에 중단 경고, 다시 열면 재개 알림과 "자리 비운 사이" 알림
- [ ] 로그아웃 상태에서 경고. PC 절전 5분 이상 후 복귀 시 불필요한 중단·재개 알림 없음
- [ ] 다른 계정 화면: 알림 없음, 화면 안내 표시. 다른 계정에 갔다 돌아와도 오알림 없음
- [ ] 미리보기에 `@channel`, `<링크>` 형태가 있어도 Slack에서 동작하지 않음
- [ ] "읽지 않음으로 표시" 시 수동 표시 안내가 붙음
- [ ] 감지 확인: 대상 계정의 수신함 탭을 하나 열면 자동으로 감지 담당 탭이 된다. 옵션의 "감지 담당 탭" 상태에 표시되는지 보고, service worker 콘솔에서 테스트 메시지 1건이 `BADGE_STATE` 1회와 `LIST_CANDIDATE` 1회를 만드는지 확인

### R2~R4 말풍선 번역·복사
- [ ] 두 채널의 받은/보낸 말풍선에 버튼. 사진·음성에는 없음
- [ ] 여러 줄, 이모지 메시지의 복사와 번역. 번역을 보이는 중에도 복사는 원문
- [ ] 같은 말풍선 재번역 시 service worker Network에 DeepL 요청 없음
- [ ] 대화 전환, 위로 스크롤 후에도 동작. 버튼 위치(툴바 겹침 4px)가 어색하지 않은지
- [ ] DeepL 키 없음 → 설정 링크, 잘못된 키 → "DeepL 키가 올바르지 않습니다"

### R5 번역 전송 (테스트 상대 계정만)
- [ ] 한글 입력 후 Enter, 전송 버튼 각각: 번역문만 1번 도착
- [ ] 한글+영어 혼합, 여러 줄(Shift+Enter), 이모지: 줄바꿈 유지, 번역 후 줄바꿈이 두 배가 되지 않음
- [ ] 조합 중 Enter를 빠르게 눌러도 글자 누락·이중 전송 없음 (macOS, Windows)
- [ ] 한글이 없으면 그대로 전송. 대상 언어 "끔"이면 한글이 그대로 전송
- [ ] DeepL 오류(잘못된 키) → 전송 안 됨, 원문 유지, 오류 표시
- [ ] 번역 중 다른 대화로 이동 → 아무것도 전송되지 않음. 번역 중 Enter 연타 → 한글 원문 안 나감
- [ ] 영어 대화 → "끔" 대화로 빠르게 전환 시 "끔" 대화에 영어 미적용. "끔" 대화로 바꾼 직후 한글 전송은 번역되지 않고, 언어 로딩 전에는 막힘
- [ ] 확장 프로그램을 다시 로드한 뒤 기존 탭에서 한글 전송 → 막히고 새로고침 안내
- [ ] 전송 후 "보낸 원문" 줄이 5초 보이고 위치가 적절함
- [ ] 상대 계정에서 번역문만 도착했는지 확인

### R6 빠른 메시지
- [ ] 선택하면 커서 위치에 들어가고 전송되지 않음. 이후 Enter로 정상 전송
- [ ] 한글 빠른 메시지는 전송 시 번역됨. 입력창 교체 후 남는 한글 없음
- [ ] 대화별 언어(A=끔, B=JA)가 대화 전환과 브라우저 재시작 후 유지
- [ ] 막대가 창 크기 변경·여러 줄 입력에서 입력창 위에 유지, Meta 대화상자가 열리면 숨음
- [ ] 막대 검색창에서 한글 조합 중 Enter가 항목을 선택하지 않음, Meta가 포커스를 가져가지 않음

## (c) 알려진 한계

- **선택자 미검증:** Instagram 목록 구조(U1), 검색 입력(U11), 목록 스크롤 요소(U12)는 예상값이다. 못 찾으면 화면에 상태가 표시된다.
- **Instagram 전송 버튼 라벨:** `Submit`과 후보 `Send`만 안다. 한국어 UI 등 다른 값이면 전송 이어가기가 버튼을 못 찾고 합성 Enter로 간다.
- **필터 상태 추정:** 필터·검색 상태를 목록 주변 컨트롤의 aria 속성과 검색어로 추정한다. 못 읽으면 필터된 목록에서 오알림이 날 수 있고, 기획서의 "필터 영역 클릭 = 화면 전환" 대체 동작은 구현하지 않았다.
- **로그인·체크포인트·captcha 판별은 휴리스틱:** 경로(`/login`, `/checkpoint` 등)와 password 입력, captcha iframe 패턴. 오탐 시 감지가 조용히 멈추고 신호는 60초 뒤 로그인 경고뿐이다.
- **입력창 재사용 가능성:** Meta가 대화 사이에 같은 Lexical 입력창을 재사용하면, 번역 삽입 도중 대화를 바꿀 때 번역문이 새 대화 입력창에 붙을 수 있다. 전송은 되지 않고 경고가 나와야 한다. 대화 전환 중 느린 번역으로 확인한다.
- **DeepL CORS(U8) 미확인:** 막히면 7-4 중계 설정이 필요하고 아직 없다.
- **수신함을 앱 안에서 벗어날 때:** 감지 담당 탭이 `/latest/home`으로 이동하면 약 2.5분 뒤(90초 타임아웃 + 알람)에야 다른 탭으로 넘어간다.
- **이어받은 직후:** 이어받은 탭의 첫 보고가 `initial:true`라 이어받는 사이 오른 건은 "자리 비운 사이" 알림으로 나간다.
- **service worker 재시작 직후 약 1초:** 이때 한글 전송은 안전하게 막히지만 안내 문구가 "새로고침"이라 오해를 줄 수 있다.
- **`selected_item_id`가 없는 입력창:** 대화 언어를 알 수 없어 한글 전송이 항상 막힌다(안전한 쪽 실패).
- **알림 지연:** 재시도와 오프라인 복구는 알람 기반이라 최대 1분 정도 늦을 수 있다.
