# Meta Inbox Helper UI/UX 수정 기획서

버전: 1.3 (2026-11-13)
대상: 이미 구현된 확장 프로그램 Meta Inbox Helper 0.1.0 (extension/)
기준 문서: meta-inbox-extension-implementation-spec.md v1.8. 이 문서는 그 기획서의 화면 부분을 바꾼다. 여기 적지 않은 동작(Slack 감지, 번역 전송 규칙, 금지 사항)은 기준 문서 그대로다. 화면을 바꾸는 데 필요한 메시지 규약과 저장 데이터의 변경은 7장과 11장에 모두 적었고, 그 밖의 규약과 데이터는 그대로다.

1.3에서 바뀐 것: 12장을 "대화 수" 기준으로 다시 씀(배지는 읽지 않은 대화 수).

1.2에서 바뀐 것: 12장 추가(Slack 알림에 미확인 대화 수 표시). 이 문서의 다른 장과 달리 12장은 화면이 아니라 Slack 알림 문구를 바꾼다.

1.1에서 바뀐 것 (현재 코드와 대조한 검토 결과 반영)

- 4-4: 대화별 언어 저장 형식을 실제 저장 형태({ lang, at }) 기준으로 다시 적고, 변환 규칙과 함께 바뀌는 코드를 명시
- 4-2: 도구 막대를 넣지 못했을 때의 번역 전송 규칙 추가
- 2장: 이벤트 전달 차단(10번), 로그인·보안 확인 화면과 Meta 대화상자(11번) 규칙 추가
- 3-4, 3-5: 언어 이름 표시 규칙, 번역 결과 언어 설정을 따르는 문구
- 3-6, 9장: 스크롤 보정의 전제 확인(V6~V8), 목록 창 잘림과 좁은 폭 확인(V9, V10), 이벤트 전달 확인(V11), 자동 테스트 항목 추가
- 6-3: 상태 판정 순서. 7장 신설: 사이트 액세스 권한 확인, 상태 표시용 저장 값, 설정 화면 메뉴 열기 등 service worker 쪽 작업
- 6-4: 빠른 메시지 버튼 사용 스위치의 위치, 점검표 완료 판정, 이미 구현된 항목 표시
- 그 밖: 3-3 판별 방식 명시, 4-5 보조 표시를 겹쳐 띄우는 방식으로 확정, 4-6에 번역 중 표시(.mbx-busy) 삭제 추가, 5장에 창이 잘릴 때의 대체 위치 추가
- 장 번호: 7장을 새로 넣어 1.0의 7~10장이 8~11장이 됐다
참고 이미지: ui-reference/ 폴더의 3장. 다른 확장 프로그램의 화면이며, 배치와 형식의 기준으로만 쓴다. 색과 세부 모양은 이 문서를 따른다.

## 0. 구현 담당자가 먼저 알아야 할 것

1. 이번 수정의 핵심은 "떠 있는 UI"를 "화면 흐름 안에 자리 잡은 UI"로 바꾸는 것이다. 지금은 말풍선 버튼이 마우스를 올릴 때만 떠서 보이고, 입력창 위 버튼도 좌표로 띄운 것이다. 수정 후에는 말풍선 아래 줄과 입력창 위 막대가 실제 자리를 차지한다.
2. 그러려면 Meta의 화면(DOM) 안에 확장 프로그램 요소를 끼워 넣어야 한다. 기준 문서 7-1의 "말풍선마다 버튼을 주입하지 않는다"는 이 문서로 대체한다. 대신 2장의 삽입 규칙을 반드시 지킨다.
3. 기준 문서의 금지 사항은 그대로다. 특히 "사용자가 누르지 않은 말풍선의 본문을 읽지 않는다"는 버튼이 항상 보이게 돼도 똑같이 적용된다. 번역이나 복사를 누른 그 말풍선만 읽는다.
4. 3장과 4장의 삽입 위치는 2026-11-13에 실제 수신함 화면에서 읽기 전용으로 확인한 구조다. 대화 1개에서 확인했으므로 Instagram 대화와 WhatsApp 대화 각각에서 다시 확인한 뒤 구현한다(9장 V1).
5. 요청 5건 중 3번(빠른 메시지)은 참고 이미지에 버튼 모양만 있고 목록 창은 없다. 목록 창은 5장에 새로 설계했다.
6. 화면만 바꾸는 작업이 아니다. service worker와 순수 로직(lib/)에도 손댈 곳이 있다: 대화별 언어 저장 형식(4-4), 사이트 액세스 권한 확인과 상태 값 저장, 설정 화면 메뉴 열기(7장). 특히 사이트 액세스 권한 확인은 기준 문서 12장에 적혀 있지만 현재 코드에는 구현돼 있지 않다.
7. 4-4의 저장 형식 변환을 잘못하면 번역을 꺼 둔 대화의 고객에게 번역문이 나간다. 변환 로직은 단위 테스트를 먼저 쓰고 구현한다.

## 1. 요청 사항과 대응

| 번호 | 요청 | 대응 | 장 |
|-|-|-|-|
| 1 | 번역하면 말풍선 아래에 번역문이 보인다. 연한 회색 배경에 검정 글씨 | 말풍선 아래에 자리를 차지하는 번역 상자 | 3 |
| 2 | 말풍선 아래에 버튼을 고정한다. 글씨만이 아니라 버튼 배경과 배치가 보여 읽기 좋게 | 텍스트 말풍선마다 항상 보이는 액션 줄, 알약 모양 버튼 | 3 |
| 3 | 빠른 메시지를 참고 이미지와 같은 형식으로 | 도구 막대 왼쪽의 아이콘 + 글자 버튼, 새 목록 창 | 5 |
| 4 | 채팅 입력창 위에 참고 이미지와 같은 버튼 | 입력창 위 전체 폭 도구 막대. 왼쪽 빠른 메시지, 오른쪽 번역 켬/끔과 언어 | 4 |
| 5 | 설정 화면 UI/UX 전면 수정 | 왼쪽 메뉴 + 상태 요약 + 설정 순서 안내로 재구성 | 6 |
| 6 | Slack 알림에 쌓여 있는 메시지 수도 보여 준다 | 알림마다 그 채널과 전체의 "미확인 대화 수"를 함께 표시 | 12 |

참고 이미지에서 가져오는 것과 가져오지 않는 것

- 가져오는 것: 말풍선 아래 액션 줄의 위치와 항목 순서(번역 보기, 언어, 원문 복사, 번역 복사), 번역문이 그 아래 이어지는 배치, 입력창 위 막대의 좌우 배치, 번역 켬/끔 스위치.
- 가져오지 않는 것: 막대의 "클리닉 안내", "지도", "협찬 항목" 버튼(이번 범위 밖), 글씨만 있는 버튼 모양(요청 2에 따라 배경 있는 버튼으로 바꾼다).

## 2. Meta 화면 안에 요소를 넣는 규칙

떠 있는 방식은 자리를 차지하지 못해 다음 말풍선을 가린다. 그래서 흐름 안에 넣는다. Meta 화면은 수시로 다시 그려지므로 아래 규칙을 지킨다.

1. 넣는 요소는 확장 프로그램이 만든 요소뿐이다. Meta가 만든 요소의 내용, 속성, 스타일, 순서는 바꾸지 않는다.
2. 넣는 요소의 최상위에는 data-mbx 속성을 붙이고 종류를 값으로 적는다(actions, toolbar). 확장 프로그램은 이 속성으로만 자기 요소를 찾고 지운다.
3. 넣는 요소 안쪽은 Shadow DOM으로 감싼다. Meta의 스타일이 들어오지 않고 확장 프로그램 스타일이 새어 나가지 않게 한다.
4. Meta가 화면을 다시 그리면서 넣은 요소가 사라질 수 있다. MutationObserver로 감지해 다시 넣는다. 다시 넣을 때 번역문 표시 상태는 메시지 ID 기준으로 복원한다(번역 캐시는 기준 문서 7-3 그대로 메모리에 있다).
5. 말풍선이 사라졌는데 액션 줄만 남으면 지운다.
6. 한 번의 변화에 대한 삽입 작업은 한 프레임에 모아서 한다. 삽입이 다시 관찰자를 깨워 무한 반복되지 않도록, 자기 요소로 인한 변화는 무시한다.
7. 삽입에 실패하거나 위치를 찾지 못하면 그 말풍선은 건너뛴다. 오류를 던져 다른 기능을 멈추지 않는다. 텍스트 말풍선이 있는 대화에서 한 곳도 넣지 못하면 기존의 떠 있는 방식으로 되돌아가지 않고, 도구 막대의 보조 표시 자리(4-5)에 "말풍선 버튼을 표시하지 못했습니다"를 대화마다 1회 표시한다. 도구 막대도 없으면 기존 토스트(util.toast)로 표시한다. 도구 막대 자체를 넣지 못한 경우는 4-2의 규칙을 따른다.
8. 확장 프로그램을 끄거나 해당 기능을 설정에서 끄면 넣은 요소를 모두 지운다.
9. 넣은 요소 때문에 대화 스크롤 위치가 튀지 않게 한다(3-6).
10. 넣은 요소 안에서 생긴 이벤트가 Meta의 핸들러로 올라가지 않게 한다. 넣은 요소의 최상위(Shadow DOM의 호스트)에서 click, dblclick, mousedown, mouseup, pointerdown, pointerup, contextmenu, keydown, keypress, keyup, input의 전파를 막는다(stopPropagation). 액션 줄을 눌렀을 때 Meta의 말풍선 선택, 답장, 반응 메뉴가 열리면 안 된다.
    - 버튼의 mousedown에서는 preventDefault를 호출해 입력창의 포커스와 커서 위치를 유지한다. 번역 상자와 검색란에서는 호출하지 않는다(글자 선택과 입력이 돼야 한다).
    - 전송 가로채기 리스너(window, capture 단계)는 넣은 요소보다 먼저 실행된다. 대상이 입력창이나 전송 버튼일 때만 동작하는 지금의 조건을 그대로 두면 서로 영향이 없다.
11. 로그인, 보안 확인, 캡차 화면(금지 사항 9번)에서는 넣은 요소를 모두 지우고 새로 넣지 않는다. Meta의 대화상자가 열려 있는 동안에는 흐름 안의 요소(액션 줄, 도구 막대)는 그대로 두고, 겹쳐 뜨는 창(빠른 메시지 목록, 언어 목록)만 닫는다. 기준 문서 12장의 "대화상자가 열리면 주입 UI를 숨긴다"는 겹쳐 뜨는 창에만 적용한다.
12. 토스트 안내에 쓰는 body 아래의 호스트 요소(mbx-root)는 그대로 둔다. 이 문서에서 없애는 것은 3-7, 4-6에 적은 것뿐이다.

## 3. 말풍선 액션 줄과 번역 상자 (요청 1, 2)

### 3-1. 모양

```
받은 메시지 (왼쪽 정렬)

  ┌──────────────────────────────┐
  │ カウンセリングの際、日本語での │   ← Meta의 말풍선 (건드리지 않음)
  │ 対応も可能でしょうか？          │
  └──────────────────────────────┘
  [번역 보기] 일본어  [원문 복사]            ← 액션 줄 (항상 보임)


번역을 누른 뒤

  ┌──────────────────────────────┐
  │ カウンセリングの際、日本語での │
  │ 対応も可能でしょうか？          │
  └──────────────────────────────┘
  [번역 숨기기] 일본어 → 한국어  [원문 복사] [번역 복사]
  ┌──────────────────────────────┐
  │ 상담 시 일본어로도 상담이      │   ← 번역 상자 (연한 회색 배경, 검정 글씨)
  │ 가능한가요?                    │
  └──────────────────────────────┘


보낸 메시지 (오른쪽 정렬): 액션 줄과 번역 상자도 오른쪽에 붙는다

                    ┌────────────────────────┐
                    │ Hello, thank you for... │
                    └────────────────────────┘
                 [번역 보기]  [원문 복사]
```

### 3-2. 넣는 위치 (확인됨)

- 말풍선 요소: `[data-message-id]`
- 이 요소의 부모는 세로 방향 flex 컨테이너이고 자식이 말풍선 하나뿐이다. align-items가 받은 메시지는 flex-start, 보낸 메시지는 flex-end다.
- 액션 줄을 이 부모의 마지막 자식으로 넣는다(말풍선의 다음 형제). 그러면 말풍선 바로 아래에 놓이고, 좌우 정렬은 부모의 align-items를 그대로 따른다. 정렬을 따로 계산하지 않는다.
- 번역 상자는 액션 줄 요소 안에 둔다. 즉 말풍선 하나에 넣는 요소는 1개다.
- 메시지 묶음 사이에는 원래 15px 간격이 있다. 액션 줄이 들어가면 말풍선 사이가 약 30px 더 벌어진다. 이것은 의도한 변화다.
- 대화 영역(`[role="region"]`) 자체가 스크롤 컨테이너다.

### 3-3. 어떤 말풍선에 넣는가

- 안에 내용이 있는 `[dir="auto"]`가 있는 말풍선에만 넣는다. 사진, 음성, 스티커, "Message can't be displayed" 말풍선에는 넣지 않는다.
- 이 판별은 지금의 sel.bubbleHasText(content/selectors.js)를 그대로 쓴다. 내용이 있는 텍스트 노드가 있는지만 보고, innerText나 textContent로 문자열을 꺼내지 않는다. 글자 내용은 읽거나 보관하지 않는다.
- 받은 메시지와 보낸 메시지 모두에 넣는다.
- 설정의 "말풍선 번역·복사 버튼 사용"이 꺼져 있으면 넣지 않는다.

### 3-4. 액션 줄 구성

왼쪽부터 다음 순서다. 보낸 메시지에서도 순서는 같고 줄 전체가 오른쪽에 붙는다.

| 항목 | 종류 | 표시 조건 | 동작 |
|-|-|-|-|
| 번역 보기 / 번역 숨기기 | 버튼 | 항상 | 번역 상자를 열고 닫는다. 처음 열 때만 DeepL을 호출하고 이후는 캐시를 쓴다 |
| 언어 표시 | 글자(버튼 아님) | 번역 전: 표시하지 않음. 번역 후: "일본어 → 한국어" | "감지 언어 → 번역 결과 언어"를 한국어 이름으로 표시한다. 코드(JA)가 아니라 이름을 쓴다 |
| 원문 복사 | 버튼 | 항상 | 말풍선 원문을 클립보드에 복사 |
| 번역 복사 | 버튼 | 번역 상자가 열려 있고 번역이 성공했을 때만 | 번역문을 클립보드에 복사 |

- 참고 이미지에는 번역 전에도 "한국어"가 표시되지만, 번역 전에는 원문 언어를 알 수 없으므로(본문을 읽지 않는다) 표시하지 않는다.
- 언어 이름
  - 화살표 오른쪽은 "한국어"로 고정하지 않는다. 설정의 번역 결과 언어(bubbleTargetLang)의 이름을 쓴다.
  - lib/constants.js에 언어 이름표(코드 → 한국어 이름)를 추가하고 액션 줄, 도구 막대, 설정 화면이 함께 쓴다. 지금의 SEND_LANGS는 보낼 때 쓰는 대상 언어 14개뿐이라 감지 언어에는 부족하다. DeepL이 감지해 돌려주는 원문 언어 코드(KO, JA, EN, ZH, ES, FR, DE, RU, VI, TH, ID, AR, PT, IT, NL, PL, TR, UK 등, 전체 목록은 DeepL 문서로 확인)를 넣는다.
  - 이름표에 없는 코드는 코드를 그대로 표시한다. 감지 언어가 응답에 없으면 번역 결과 언어 이름만 표시한다.
- 번역 캐시는 지금처럼 번역 결과 언어를 함께 기억한다. 설정에서 번역 결과 언어를 바꾸면 이전 언어로 번역한 캐시는 쓰지 않고 다시 호출한다.
- 복사 성공 시 해당 버튼 글자를 1.5초간 "복사됨"으로 바꾼다. 버튼 폭이 흔들리지 않게 최소 폭을 고정한다.
- 번역 중에는 "번역 보기" 버튼을 "번역 중…"으로 바꾸고 누를 수 없게 한다.

### 3-6. 스크롤 처리

- 대화를 열면 여러 말풍선에 액션 줄이 한꺼번에 들어가 전체 높이가 늘어난다. 넣기 직전에 대화 영역이 맨 아래에 있었으면(바닥에서 40px 이내) 넣은 뒤에도 맨 아래로 맞춘다. 그렇지 않으면 화면에 보이던 말풍선의 위치가 유지되도록 늘어난 높이만큼 scrollTop을 보정한다.
- 번역 상자를 열 때: 상자가 화면 아래로 잘리면 상자가 다 보이는 만큼만 스크롤한다. 맨 아래 말풍선이었다면 맨 아래로 맞춘다.
- 스크롤 보정은 넣은 요소로 인한 높이 변화에 대해서만 한다. 사용자의 스크롤을 주기적으로 되돌리지 않는다. 기준 문서의 "자동 스크롤 금지"는 대화를 읽기 위해 스크롤을 움직이는 것을 금지한 것이고, 이 보정은 화면이 튀지 않게 하는 것이라 해당하지 않는다.
- 위로 스크롤해 이전 메시지가 추가로 그려지면 그 말풍선들에도 같은 방식으로 넣는다.
- 도구 막대(4장)가 들어가면 대화 영역이 36px 줄어든다. 이때도 같은 규칙을 적용한다(맨 아래에 있었으면 맨 아래 유지).

이 절은 "scrollTop이 0이면 맨 위, 커질수록 아래"인 일반적인 스크롤을 전제로 한다. 구현 전에 아래를 확인하고(9장 V6~V8), 결과에 맞춰 보정 방식을 정한다.

- 대화 영역이 flex-direction: column-reverse이면 scrollTop의 기준이 반대다(맨 아래가 0, 위로 갈수록 음수). 이 경우 "바닥에서 40px 이내" 판정과 보정 방향을 그에 맞게 바꾼다. 맨 아래 고정은 브라우저가 알아서 해 주므로 직접 맞추지 않아도 될 수 있다.
- 브라우저의 스크롤 앵커링(overflow-anchor)이 대화 영역에서 동작하면 화면에 보이던 말풍선 위치를 브라우저가 이미 유지한다. 이때 scrollTop을 또 보정하면 두 번 움직인다. 앵커링이 동작하면 "위로 올려 둔 상태"의 보정은 하지 않고 "맨 아래 유지"만 한다.
- 액션 줄을 넣어 높이가 늘어난 것 때문에 Meta의 이전 메시지 불러오기가 실행되면 안 된다. 실행되면 대화를 열 때마다 불러오기가 연달아 일어난다. 확인되면 구현을 멈추고 보고한다.

## 4. 입력창 위 도구 막대 (요청 4)

### 4-1. 모양

```
├──────────────────────────────────────────────────────────────┤  ← 위쪽 구분선
│ ⚡ 빠른 메시지                          번역 ON │ 일본어 ▾  (●━) │  ← 도구 막대 (높이 36px)
├──────────────────────────────────────────────────────────────┤
│  [ Meta의 입력창 ]                                            │
```

- 대화 패널 전체 폭을 쓰는 한 줄이다. 왼쪽에 빠른 메시지 버튼, 오른쪽에 번역 조작부가 있다.
- 높이 36px, 좌우 안쪽 여백 12px, 배경 흰색, 위쪽에 1px 구분선(#E4E6EB).

### 4-2. 넣는 위치 (확인됨)

- 대화 패널은 세로 방향 flex 컨테이너이고 자식이 3개다. 그중 세 번째가 입력창 영역이다(대화 영역과 입력창 영역의 공통 부모).
- 도구 막대를 이 컨테이너 안, 입력창 영역 바로 앞에 넣는다. 그러면 대화 영역이 막대 높이만큼 줄어들고 입력창은 그대로다.
- 입력창 영역을 찾는 방법: 입력창(`[role="textbox"][data-lexical-editor]`)에서 부모로 올라가며, 대화 영역(`[role="region"]`)을 함께 포함하는 첫 조상을 찾는다. 그 조상의 자식 중 입력창을 포함하는 것이 입력창 영역이다. 단계 수를 고정하지 않는다.
- 대화를 바꾸면 입력창 영역이 다시 그려질 수 있다. 막대가 사라지면 다시 넣는다. 한 화면에 막대는 1개만 있어야 한다.
- 입력창이 없는 화면(대화 미선택, 댓글 탭 등)에서는 넣지 않는다.
- 대화 패널 폭은 약 400px이다(기준 문서 3-5). 막대 내용이 한 줄에 들어가지 않으면 줄바꿈하지 않고 다음 순서로 줄인다: 언어 버튼의 이름을 최대 120px에서 말줄임 → 빠른 메시지 버튼의 글자를 숨기고 아이콘만 표시(aria-label은 유지).

도구 막대를 넣지 못했을 때

전송 가로채기는 window 리스너라 막대가 없어도 계속 동작한다. 그대로 두면 스위치도, 번역 중 표시도 없이 번역 전송이 일어난다. 그래서 다음과 같이 한다.

- 입력창이 있는 대화 화면인데 5초 넘게 막대를 넣지 못하면 "막대 없음" 상태로 본다. 막대가 들어가면 즉시 풀린다.
- 막대 없음 상태에서는 번역 흐름을 시작하지 않는다. 번역해서 보내야 하는 입력(설정의 "한글 입력을 번역해 전송"이 켜져 있고, 이 대화의 번역이 켜져 있고, 입력에 한글이 있음)이면 전송을 막고, 기존 토스트로 "번역 도구 막대를 표시하지 못해 한글 메시지 전송을 막았습니다. 새로고침해도 같으면 설정에서 '한글 입력을 번역해 전송'을 끄세요"를 표시한다.
- 그대로 통과하는 경우: 한글이 없는 입력, 설정에서 번역 전송을 끈 경우, 이 대화의 번역을 사용자가 이미 꺼 둔 경우. 대화별 켬/끔은 막대 없이도 service worker에서 불러오므로, 꺼 둔 대화(한국어로 상담하는 고객)까지 막을 이유가 없다.
- 판정 위치: lib/sendgate.js의 decideSend에서 "⑦ 이 대화는 번역 끔" 다음, "⑧ 직전 번역 결과 그대로 다시 누름" 앞에 둔다(새 결과값 block_no_toolbar). 기준 문서 8장의 원칙 "실패하면 전송하지 않는다"를 따른 것이다.
- 로그인, 보안 확인 화면이라 막대를 지운 경우(2장 11번)는 지금의 block_screen 처리가 그대로 적용된다.

### 4-4. 오른쪽: 번역 조작부

구성: 상태 글자, 구분선, 언어 버튼, 스위치

저장 방식 변경

현재 저장 형태(lib/threadlang.js)는 기준 문서의 설명과 달리 문자열이 아니라 객체다. 대화마다 { lang, at }이고, lang은 언어 코드 또는 "OFF", at은 저장 시각이다. at은 500개를 넘을 때 오래된 것부터 지우는 기준이다.

- 새 형태: { lang: "JA", on: true, at: 1731400000000 }. lang에는 언어 코드만 들어간다. "OFF"는 더 이상 lang에 넣지 않는다. at은 그대로 둔다.
- 끈 뒤 다시 켰을 때 언어를 기억하기 위한 변경이다. 끄면 lang은 그대로 두고 on만 false로 바꾼다.

읽을 때의 변환 (getThreadLang 한 곳에서 한다. 저장된 값을 한꺼번에 고쳐 쓰지 않고, 다음에 그 대화를 저장할 때 새 형태로 쓴다)

| 저장된 값 | 읽은 결과 |
|-|-|
| { lang: 코드, on: true 또는 false, at } | 그대로 |
| { lang: 코드, at } (on 없음) | { lang: 코드, on: true } |
| { lang: "OFF", at } | { lang: 기본 언어, on: false } |
| 문자열 "OFF" (방어용. 실제로는 저장된 적 없음) | { lang: 기본 언어, on: false } |
| 문자열 언어 코드 (방어용) | { lang: 코드, on: true } |
| 값 없음 | { lang: 기본 언어, on: true }. 저장하지는 않는다 |
| { lang: 지원 목록에 없는 코드 또는 잘못된 값, on: false, at } | { lang: 기본 언어, on: false }. 꺼짐은 유지하고 언어만 기본값으로 바꾼다 |
| 그 밖의 잘못된 값, 지원 목록에 없는 코드(on이 false가 아닌 경우) | 값 없음과 같게 처리 |

- 원칙은 하나다: 저장된 값에서 꺼짐(on: false 또는 "OFF")을 읽을 수 있으면 결과는 반드시 꺼짐이다. 언어를 알 수 없을 때만 기본 언어로 바꾼다. 표는 위에서부터 차례로 적용한다.
- 기본 언어는 읽는 시점의 설정 sendTargetLang이다.
- 꺼 둔 대화가 켜짐으로 읽히면 번역을 꺼 둔 고객에게 번역문이 나간다. 위 표에서 결과가 on: false인 줄(3, 4, 7번째)은 반드시 단위 테스트로 고정한다.
- 정리(500개 초과 삭제) 때 옛 형태의 항목도 유효한 항목으로 남겨야 한다. 지금의 validEntry가 새 형태와 옛 형태를 모두 받아들이게 한다.

함께 바뀌는 곳

- lib/threadlang.js: getThreadLang이 { lang, on }을 돌려준다. setThreadLang이 on을 받는다.
- lib/constants.js: isValidThreadLang은 언어 코드만 허용한다("OFF" 제외).
- 메시지 규약(11장): SET_THREAD_LANG {threadId, lang, on}, GET_THREAD_LANG 응답 {threadId, lang, on}. on이 불리언이 아니면 service worker가 거부한다.
- lib/sendgate.js: decideSend의 "⑦ 이 대화는 번역 끔" 조건을 lang === "OFF"에서 on === false로 바꾼다. 언어의 유효성은 여기서 다시 따지지 않는다. getThreadLang이 항상 유효한 코드를 돌려주므로 판정은 on 하나만 본다(위 변환 표와 다른 규칙을 두 군데에 두지 않는다).
- content/composer.js: 대화별 상태를 { lang, on }으로 들고, 불러오는 중은 지금처럼 null이다. 응답의 threadId가 현재 대화와 같을 때만 적용하는 규칙, 500ms 재요청 규칙은 그대로다.
- 가로채기 조건(기준 문서 8-2의 2번)은 "현재 대화의 on이 true다"로 읽는다. 나머지 규칙은 그대로다. 불러오는 중에는 한글 전송을 막는 규칙도 그대로다.

### 4-5. 보조 표시

- 전송 직후 원문 표시(기준 문서 8-7): 막대 바로 위에 한 줄로 5초간 표시한다. "보낸 원문: 안녕하세요…" 형태, 12px, #65676B, 한 줄을 넘으면 말줄임.
- 안내와 오류(번역 실패, 설정 불러오는 중, 권한 꺼짐 등): 같은 자리에 표시한다. 오류는 #B3261E. 사용자가 닫거나 다음 입력을 시작하면 사라진다.
- 수신함 화면의 "알림 대상 계정이 아닙니다" 같은 감지 관련 안내는 이 막대가 아니라 기존 위치를 유지한다.
- 이 보조 표시 줄은 자리를 차지하지 않는다. 도구 막대 요소 안에서 position: absolute로 막대 위에 겹쳐 띄운다(배경 흰색, 막대와 같은 폭). 5초짜리 표시 때문에 대화 영역 높이가 바뀌어 스크롤이 움직이면 안 되기 때문이다. 한 번에 하나만 표시하고, 오류가 원문 표시보다 우선한다.
- 지금 토스트로 표시하는 번역 전송 관련 안내(기준 문서 8-6의 문구들)는 막대가 있으면 이 자리에, 없으면 토스트로 표시한다.

### 4-6. 없애는 것

- 입력창 위에 좌표로 띄우던 막대(.mbx-bar), 입력창 테두리 표시(.mbx-outline), 입력창에 겹쳐 그리던 번역 중 표시(.mbx-busy)는 삭제한다. 번역이 켜져 있다는 표시는 "번역 ON"과 파란 스위치가, 번역 중 표시는 조작부의 "번역 중…"이 대신한다.
- 입력창 위치를 따라가기 위한 좌표 계산(ResizeObserver, scroll·resize 때의 위치 갱신)도 필요 없어진다.

## 5. 빠른 메시지 목록 창 (요청 3)

참고 이미지에는 버튼만 있어 목록 창은 새로 설계한다.

```
┌────────────────────────────────────────┐
│ 🔍 제목, 본문, 태그 검색                 │
├────────────────────────────────────────┤
│ 예약 양식                         #예약  │  ← 제목(굵게) + 태그
│ 예약을 위해 아래 정보를 보내 주세요...   │  ← 본문 2줄 미리보기
├────────────────────────────────────────┤
│ 위치 안내                         #안내  │
│ 저희 클리닉은 홍대입구역 3번 출구에서... │
├────────────────────────────────────────┤
│                              설정에서 관리 │
└────────────────────────────────────────┘
⚡ 빠른 메시지
```

- 위치: 빠른 메시지 버튼 바로 위, 왼쪽 정렬. 도구 막대에서 4px 띄운다.
- 크기: 폭 360px(대화 패널이 좁으면 패널 폭에서 24px을 뺀 값), 목록 최대 높이 320px, 넘으면 목록 안에서 스크롤.
- 모양: 배경 흰색, 모서리 반경 12px, 그림자 0 4px 16px rgba(0,0,0,0.15), 테두리 1px #E4E6EB.
- 이 창은 대화 영역 위에 겹쳐 뜬다(자리를 차지하지 않는다). 대화 패널의 flex 컨테이너에 넣지 않고 도구 막대 요소 안에서 position: absolute로 띄운다.
- 대화 패널이나 그 조상에 overflow: hidden이 걸려 있으면 이 창과 언어 목록(4-4)이 잘린다(9장 V9). 잘리면 두 창만 body 아래의 기존 호스트(mbx-root)로 옮겨 position: fixed로 띄우고, 열 때와 창 크기가 바뀔 때 버튼 위치를 기준으로 좌표를 잡는다. 겹쳐 뜨는 창이므로 이 경우는 2장의 "흐름 안에 넣는다"에 어긋나지 않는다.
- Meta의 대화상자가 열리거나 대화가 바뀌면 닫는다(2장 11번).
- 항목: 제목 14px 굵기 600 #1C1E21, 본문 미리보기 13px #65676B 최대 2줄 말줄임, 태그는 오른쪽에 작은 알약(11px, 배경 #F0F2F5). 안쪽 여백 10px 12px. 마우스를 올리거나 방향키로 선택된 항목은 배경 #F0F2F5.
- 검색: 창이 열리면 검색란에 포커스. 입력할 때마다 제목, 본문, 태그로 걸러낸다. 결과가 없으면 "검색 결과가 없습니다".
- 키보드: 위아래 방향키로 이동, Enter로 선택, Esc로 닫기. 창 밖을 누르면 닫힌다.
- 선택하면 본문을 입력창 커서 위치에 넣고 창을 닫고 입력창에 포커스를 돌려준다. 전송하지 않는다(기준 문서 9장 그대로).
- 항목이 하나도 없으면 "저장된 빠른 메시지가 없습니다"와 [설정에서 추가] 버튼을 보여 준다.
- 아래쪽 "설정에서 관리"와 [설정에서 추가]를 누르면 설정 화면의 빠른 메시지 메뉴(#quick)가 열린다. 여는 방법은 7-3을 따른다.
- 이 창 안에서 누른 Enter는 번역 전송 가로채기의 대상이 아니다.

## 6. 설정 화면 전면 개편 (요청 5)

### 6-1. 지금 화면의 문제

- 한 페이지에 8개 구역이 세로로 길게 이어지고, 처음 설정할 때 필요한 순서와 화면 순서가 다르다(빠른 메시지가 맨 위, 상태가 맨 아래).
- 지금 동작하는지 안 하는지가 맨 아래까지 내려가야 보인다.
- 2026-11-12에 실제로 겪은 문제(사이트 액세스 권한이 꺼져 번역과 Slack이 모두 실패)를 이 화면에서 알 수 없었다.
- "Slack"과 "Slack 연결"이 별도 구역으로 나뉘어 있고, 안내 문구가 길게 깔려 있어 조작할 항목이 묻힌다.

### 6-2. 새 구조

```
┌──────────────────────────────────────────────────────────────────────┐
│ Meta Inbox Helper                      ● 감지 정상  ● Slack 정상  ● 번역 정상 │  ← 상단 상태 줄
├───────────────┬──────────────────────────────────────────────────────┤
│  시작하기      │                                                      │
│  Slack 알림    │   (선택한 메뉴의 내용)                                │
│  번역          │                                                      │
│  빠른 메시지   │                                                      │
│  도움말        │                                                      │
└───────────────┴──────────────────────────────────────────────────────┘
```

- 왼쪽 메뉴 5개, 오른쪽 내용 영역. 전체 최대 폭 960px, 가운데 정렬. 메뉴 폭 200px.
- 메뉴는 주소의 해시와 연결한다(#start, #slack, #translate, #quick, #help). 수신함 화면의 [설정 열기], [설정에서 추가] 링크는 해당 메뉴로 바로 들어온다(7-3). 해시가 없거나 모르는 값이면 시작하기를 연다.
- 해시가 붙은 주소에서 보낸 메시지도 service worker가 설정 화면의 메시지로 받아들인다. 지금의 발신자 판정(lib/settings.js의 classifySender)이 이미 "#"이 붙은 주소를 허용하므로 바꾸지 않는다.
- 창 폭이 720px보다 좁으면 메뉴를 위쪽 가로 탭으로 바꾼다.
- 상단 상태 줄은 어느 메뉴에서나 보인다.

### 6-3. 상단 상태 줄

세 가지 상태를 색 점과 글자로 보여 준다. 누르면 관련 메뉴로 이동한다(감지와 Slack은 Slack 알림, 번역은 번역. 사이트 액세스 권한 때문에 빨강이면 시작하기).

각 항목은 아래 표의 위에서부터 차례로 따져, 처음 해당하는 줄의 색을 쓴다.

감지

| 순서 | 조건 | 색 | 글자 |
|-|-|-|-|
| 1 | 알림 대상 계정 미지정 | 회색 | 설정 필요 |
| 2 | 마지막 신호가 실패 신호(로그인 화면, 화면 구조를 찾지 못함) | 빨강 | 확인 필요 |
| 3 | 한 번이라도 감지한 뒤 3분 넘게 정상 신호 없음(탭이 닫힌 경우 포함. Slack으로 중단 경고가 나가는 조건과 같다) | 빨강 | 중단됨 |
| 4 | 최근 90초 안에 정상 신호 있음 | 초록 | 정상 |
| 5 | 그 밖(수신함 탭을 아직 연 적 없음, 신호가 90초~3분 사이로 끊김) | 노랑 | 수신함 탭 확인 |

Slack

| 순서 | 조건 | 색 | 글자 |
|-|-|-|-|
| 1 | Webhook 미설정 또는 Slack 알림 사용 안 함 | 회색 | 설정 필요 / 사용 안 함 |
| 2 | hooks.slack.com 사이트 액세스 권한 꺼짐 | 빨강 | 권한 필요 |
| 3 | 마지막 전송 실패 | 빨강 | 확인 필요 |
| 4 | 재시도 대기 중인 알림 있음 | 노랑 | 재시도 중 |
| 5 | 전송한 적 없음(테스트 전) | 노랑 | 테스트 필요 |
| 6 | 마지막 전송 성공 | 초록 | 정상 |

번역

| 순서 | 조건 | 색 | 글자 |
|-|-|-|-|
| 1 | 키 미설정 | 회색 | 설정 필요 |
| 2 | 키에 해당하는 DeepL 주소(api.deepl.com 또는 api-free.deepl.com)의 사이트 액세스 권한 꺼짐 | 빨강 | 권한 필요 |
| 3 | 마지막 결과가 키 오류 또는 한도 초과 | 빨강 | 확인 필요 |

| 6 | 무료 키 사용 중 | 노랑 | 무료 키 |

- 상태는 화면을 열 때 읽고, 열려 있는 동안 10초마다 갱신한다.
- 갱신은 GET_STATUS 메시지 한 번으로 한다. 이 갱신에서 DeepL이나 Slack으로 요청을 보내지 않는다. 번역 상태는 service worker가 저장해 둔 마지막 확인 결과를 읽는다(7-2). DeepL 사용량은 [키 확인]을 누를 때만 조회한다.
- 색만으로 구분하지 않는다. 표의 글자를 항상 함께 적는다.

### 6-4. 메뉴별 내용

시작하기

- 처음 설정에 필요한 단계를 순서대로 보여 주는 점검표다. 각 단계는 완료 표시와 [설정하기] 버튼이 있고, 버튼은 해당 메뉴로 이동한다.

  1. 사이트 액세스 권한 허용. business.facebook.com, hooks.slack.com, api.deepl.com, api-free.deepl.com 네 곳의 허용 여부를 각각 표시한다. 빠진 것이 있으면 [권한 허용] 버튼을 보여 준다(chrome.permissions.request, 사용자 클릭 필요). 이 기능은 현재 코드에 없으므로 새로 만든다(7-1).
  2. Slack Webhook 주소 입력
  3. 알림 대상 계정 지정
  4. DeepL 키 입력
  5. Slack 테스트 메시지 보내기

- 완료 판정: 1은 네 곳 모두 허용, 2는 Webhook 저장됨, 3은 assetId 저장됨, 4는 키 저장됨, 5는 지금의 Webhook 주소로 테스트 전송에 성공한 기록이 있음(7-2의 slackTestOkAt. Webhook 주소를 바꾸면 지워진다).
- Slack 알림을 쓰지 않는 경우(Slack 알림 사용 스위치 끔) 2, 3, 5는 "사용 안 함"으로 표시하고 완료로 센다. DeepL 키를 넣지 않으면 4는 미완료로 남는다.

- 점검표 아래에 "현재 상태" 카드: 마지막 감지 신호 시각, 감지 담당 탭 유무, 마지막 Slack 전송 결과와 시각, 대기 중 알림 수, 최근 오류.
- 모든 단계가 끝나면 점검표를 접고 "설정이 완료되었습니다"와 현재 상태 카드만 보여 준다.

Slack 알림

- 카드 1 "연결": Slack 알림 사용 스위치, Webhook 주소(가려서 표시, [변경]), [테스트 메시지 보내기]와 결과.
  - 테스트 메시지는 재시도 대기열에 넣지 않는다. 실패하면 그 자리에서 실패 이유를 표시하고 끝낸다. (2026-11-12에 실패한 테스트 3건이 대기열에 쌓였다가 나중에 한꺼번에 전송된 일이 있었다.) 이 동작은 이미 구현돼 있다(커밋 fc288ab). 이번에는 화면 표시와 성공 기록(7-2)만 더한다.
- 카드 2 "알림 대상 계정": 계정 이름, 지정된 계정 번호, [현재 수신함을 알림 대상으로 지정].
- 카드 3 "알림 내용": 미리보기 길이, 전화번호 가리기. 아래에 설정을 반영한 Slack 알림 예시를 미리 보여 준다.
- 카드 4 "운영 안내": 접을 수 있는 영역. 수신함 탭 유지, 탭 2개 사용, 탭 절전 제외, 여러 사람이 설치할 때 한 대에서만 켜기.

번역

- 카드 1 "DeepL 연결": 키(가려서 표시, [변경]), [키 확인]과 결과(요금제 종류, 이번 달 사용량 막대). 무료 키일 때의 안내는 노란 안내 상자 한 개로 줄인다.
- 카드 2 "말풍선 번역": 말풍선 번역·복사 버튼 사용 스위치, 번역 결과 언어.
- 카드 3 "보낼 때 번역": 한글 입력을 번역해 전송 스위치, 기본 대상 언어. 스위치 아래에 한 줄 설명 "입력창 위 스위치로 대화마다 켜고 끌 수 있습니다".

```
├─────────────────────────────┤                                    │
│ 3개      [가져오기][내보내기]│                                    │
└─────────────────────────────┴────────────────────────────────────┘
```

- 맨 위에 "빠른 메시지 버튼 사용" 스위치를 둔다(설정 quickRepliesEnabled. 지금은 번역 구역에 있다). 끄면 수신함의 빠른 메시지 버튼만 숨기고, 아래의 관리 화면은 그대로 쓸 수 있다.
- 왼쪽 목록, 오른쪽 편집 영역의 2단 구성. 목록에서 고르면 오른쪽에서 바로 고친다.
- 목록: 제목과 태그. 끌어서 순서를 바꾼다(끌기가 어려운 환경을 위해 위, 아래 버튼도 유지한다).
- 편집: 제목(50자), 본문(2000자, 글자 수 표시), 태그. [저장]을 눌러야 반영된다. 저장하지 않고 다른 항목을 고르면 "저장하지 않은 변경이 있습니다"를 묻는다.
- 삭제는 확인을 한 번 받는다.
- 가져오기, 내보내기는 목록 아래에 둔다. 가져오기의 검증과 "합치기 / 전체 교체" 선택, 적용 전 요약은 기준 문서 10-3 그대로다.
- 항목이 없으면 오른쪽에 "첫 빠른 메시지를 만들어 보세요"와 [+ 새 메시지].
- 바꾼 내용은 수신함 화면에 새로고침 없이 반영된다(기준 문서 10-1 그대로).

도움말

- 알려진 한계(기준 문서 14장의 사용자용 문구), 자주 생기는 문제와 해결(아래 3개는 반드시 포함), 버전 정보.
  - 번역과 Slack이 모두 안 될 때: 사이트 액세스 권한을 확인한다.
  - "감지가 중단되었습니다" 알림이 왔을 때: 수신함 탭이 열려 있는지 확인하고 새로고침한다. 확장 프로그램을 수정하거나 다시 로드한 뒤에는 수신함 탭도 새로고침해야 한다.
  - 한글이 번역되지 않고 전송될 때: 입력창 위 스위치가 켜져 있는지 확인한다.

### 6-5. 공통 화면 규칙

- 카드: 배경 흰색, 테두리 1px #E4E6EB, 모서리 반경 12px, 안쪽 여백 20px, 카드 사이 16px. 페이지 배경 #F0F2F5.
- 카드마다 제목(16px, 굵기 600)과 한 줄 설명(13px, #65676B)을 둔다. 긴 안내문은 "자세히" 접기 안에 넣는다.
- 켜고 끄는 항목은 체크박스 대신 스위치를 쓴다.
- 스위치, 선택 목록은 바꾸는 즉시 저장하고 오른쪽 아래에 "저장됨" 알림을 2초간 띄운다. 글자를 입력하는 항목(Webhook 주소, 키, 계정 이름, 빠른 메시지)은 [저장] 버튼을 눌러야 저장한다.
- 입력 오류는 해당 입력란 바로 아래에 빨간 글씨로 표시한다. Webhook 주소는 https://hooks.slack.com/ 으로 시작하는지 입력 즉시 확인한다.
- 비밀값은 저장 후 다시 보여 주지 않는다. 가린 표시와 [변경]만 둔다.
- 주요 버튼(파랑 #1877F2, 흰 글자)은 카드마다 1개만 둔다. 나머지는 회색 버튼.
- 삭제, 전체 교체 같은 되돌릴 수 없는 동작은 빨간 글자 버튼으로 구분하고 확인을 받는다.
- 모든 조작은 키보드로 가능해야 하고, 입력란에는 label을 연결한다.

## 7. service worker 쪽 작업

화면을 바꾸려면 아래 세 가지가 service worker에 필요하다. 기준 문서의 다른 동작은 건드리지 않는다.

### 7-1. 사이트 액세스 권한 확인 (신규)

기준 문서 12장에 적혀 있지만 현재 코드에는 없다. 이번에 구현한다.

- 대상: https://business.facebook.com/*, https://hooks.slack.com/*, https://api.deepl.com/*, https://api-free.deepl.com/* 네 곳.
- service worker는 GET_STATUS를 처리할 때와, DeepL 또는 Slack 요청이 네트워크 오류로 실패했을 때 chrome.permissions.contains로 각각 확인한다.
- 요청이 네트워크 오류로 실패했고 그 주소의 권한이 꺼져 있으면 오류 코드를 PERMISSION_OFF로 돌려준다. 문구는 "확장 프로그램의 사이트 액세스 권한이 꺼져 있습니다"다. "잠시 후 다시 시도하세요"로 표시하지 않는다.
  - 번역(TRANSLATE, CHECK_DEEPL_KEY): 응답 {ok: false, code: "PERMISSION_OFF"}. 말풍선 번역 상자(3-5)와 번역 전송 실패 안내가 이 문구를 쓴다.
  - Slack: 테스트 메시지는 그 자리에서 이 이유로 실패를 표시한다. 실제 알림은 지금처럼 대기열에 남기고, 마지막 오류에 이 코드를 기록한다.
- [권한 허용] 버튼은 설정 화면에서 chrome.permissions.request를 직접 부른다(사용자 클릭 안에서만 동작하므로 service worker를 거치지 않는다). 빠진 주소만 요청한다. 결과를 받은 뒤 상태를 바로 다시 읽는다.
- 네 곳은 이미 manifest.json의 host_permissions에 있다. 사용자가 꺼 둔 host_permissions 주소를 chrome.permissions.request로 다시 허용받을 수 있는지는 확인하지 못했다(9장 V12). 되면 manifest.json은 바꾸지 않는다. 안 되면 [권한 허용] 버튼 대신 "브라우저의 확장 프로그램 관리 화면에서 사이트 액세스를 허용하세요"라는 안내와 그 화면을 여는 방법을 표시한다. 어느 쪽이든 허용 여부 표시(chrome.permissions.contains)는 그대로 쓴다.

### 7-2. 상태 표시용 저장 값 (추가)

6-3의 상태 줄과 6-4의 점검표에 필요한데 지금 저장하지 않는 값이다. chrome.storage.local에 statusInfo를 추가한다.

```json
{
  "statusInfo": {
    "deepl": { "checkedAt": 0, "ok": false, "code": "", "used": 0, "limit": 0 },
    "slackTestOkAt": 0
  }
}
```

- deepl: [키 확인](CHECK_DEEPL_KEY)의 결과를 저장한다. 번역 요청(TRANSLATE)이 키 오류나 한도 초과로 실패하면 ok를 false로, code를 그 코드로 바꾼다. 번역 요청이 성공하면 ok를 true로 바꾼다(used와 limit은 그대로). 키를 바꾸면 초기화한다(checkedAt 0 = 확인한 적 없음).
- 무료 키 여부는 저장하지 않는다. 키가 ":fx"로 끝나는지를 service worker가 GET_STATUS 때 판단해 알려 준다.
- slackTestOkAt: 테스트 메시지 전송에 성공한 시각. Webhook 주소를 바꾸면 0으로 되돌린다.
- 메시지 본문, 키, Webhook 주소는 넣지 않는다.
- GET_STATUS 응답에 추가하는 값: permissions({주소: 허용 여부} 4개), deepl(위 값과 무료 키 여부, 키 설정 여부), slackTestOkAt, Webhook 설정 여부, Slack 사용 여부, 재시도 대기 건수, 마지막 감지 신호의 정상/실패 구분과 실패 이유, 한 번이라도 감지했는지. 이미 있는 값(마지막 신호 시각, 마지막 전송 결과, 대기열 건수, 최근 오류, 계정 번호, 감지 담당 탭)은 그대로 둔다. 비밀값은 넣지 않는다.
- 추가 값의 출처: 재시도 대기 건수는 slackQueue에서 attempts가 1 이상인 항목 수로 계산한다. 감지 실패 여부는 watcherState에 이미 있는 실패 기록(failAlerts)으로 판단한다. 6-3의 표를 만드는 데 저장돼 있지 않은 값이 더 필요하면(예: 마지막 실패 신호의 이유) statusInfo 아래에 추가한다.
- 기존 저장 값(settings, quickReplies, watcherState, slackQueue, sentKeys)의 구조는 바꾸지 않는다. 바뀌는 것은 threadLangs의 값 형식(4-4)과 이 statusInfo 추가뿐이다.

### 7-3. 설정 화면의 특정 메뉴 열기

지금의 OPEN_OPTIONS는 chrome.runtime.openOptionsPage()만 부른다. 이 함수는 주소에 해시를 붙일 수 없어 원하는 메뉴로 들어갈 수 없다.

- OPEN_OPTIONS에 section을 추가한다: {section: "start" | "slack" | "translate" | "quick" | "help"}. 없거나 모르는 값이면 "start"로 처리한다.
- service worker는 section을 chrome.storage.session의 pendingOptionsSection에 적고 openOptionsPage()를 부른다. 이미 열려 있는 설정 탭이 있으면 그 탭이 앞으로 오고, 없으면 새로 열린다.
- 설정 화면은 열릴 때 이 값을 읽어 해당 메뉴로 이동한 뒤 값을 지운다. 이미 열려 있는 동안에는 chrome.storage.onChanged로 이 값의 변화를 받아 같은 처리를 한다.
- 저장하지 않은 빠른 메시지 변경이 있는 상태에서 다른 메뉴로 옮겨야 하면 6-4의 "저장하지 않은 변경이 있습니다" 확인을 먼저 거친다.
- tabs 권한은 추가하지 않는다.

말풍선 액션 줄

- Instagram, WhatsApp 각각에서 받은 메시지와 보낸 메시지에 액션 줄이 항상 보이는지

- 여러 줄 메시지의 줄바꿈이 번역 상자에서 유지되는지
- 대화를 열었을 때 화면이 맨 아래에 머무는지, 위로 올려 둔 상태에서 화면이 튀지 않는지
- 대화를 바꿨다 돌아왔을 때 열어 둔 번역이 복원되는지
- 메시지가 200개 이상인 대화에서 스크롤이 버벅이지 않는지
- 새 메시지가 도착했을 때 그 말풍선에도 액션 줄이 붙는지
- 누르지 않은 말풍선의 본문이 DeepL로 전송되지 않는지(네트워크 요청으로 확인)
- 설정의 번역 결과 언어를 영어로 바꿨을 때 언어 표시가 "일본어 → 영어"로 나오고, 영어 메시지에는 "이미 영어입니다"가 나오는지
- 액션 줄과 번역 상자를 눌러도 Meta의 말풍선 동작이 실행되지 않고, 번역문을 드래그해 선택할 수 있는지
- 로그인, 보안 확인 화면이 뜨면 넣은 요소가 모두 사라지는지

도구 막대

- 대화를 선택하면 입력창 위에 막대가 1개만 보이는지, 대화를 여러 번 바꿔도 중복되지 않는지
- 스위치를 끄면 한글이 그대로 전송되고, 다시 켜면 직전 언어로 번역되는지
- 언어를 바꾸면 그 대화에만 적용되고 다른 대화에는 영향이 없는지
- 대화를 바꾼 직후 "번역 …" 상태에서 한글 전송이 막히는지
- 기존에 저장된 대화별 언어 값이 새 형식으로 올바르게 읽히는지. 수정 전 버전에서 "끔"으로 해 둔 대화를 수정 후에 열었을 때 스위치가 꺼져 있고 한글이 그대로 전송되는지(반드시 실제 저장 값으로 확인)
- 막대를 넣지 못한 상태(개발자 도구로 삽입 위치를 못 찾게 만들어 확인)에서 한글 전송이 막히고 안내가 뜨는지, 영어 입력과 번역을 꺼 둔 대화의 한글 입력은 그대로 전송되는지
- 전송 직후의 "보낸 원문" 표시가 떴다 사라질 때 대화 스크롤이 움직이지 않는지
- 대화 패널이 좁을 때 막대가 두 줄로 넘치지 않는지
- 번역 전송, 빠른 메시지 삽입 등 기준 문서 13-3의 R5, R6 항목이 그대로 통과하는지

빠른 메시지 목록 창

- 검색, 방향키, Enter, Esc가 동작하는지
- 선택 시 입력창에 들어가고 전송되지 않는지
- 창 밖을 누르면 닫히는지, 대화 패널이 좁아도 창이 화면 밖으로 나가지 않는지

설정 화면

- 처음 설치한 상태에서 "시작하기" 점검표만 따라가면 설정이 끝나는지
- 사이트 액세스 권한을 일부 끈 상태에서 상단 상태와 점검표가 이를 알려 주고 [권한 허용]으로 해결되는지
- 권한이 꺼진 상태에서 테스트 메시지를 눌렀을 때 대기열에 쌓이지 않고 실패로 끝나는지
- 수신함 화면의 설정 링크가 해당 메뉴로 열리는지. 설정 탭이 이미 열려 있을 때도 그 탭이 앞으로 오면서 메뉴가 바뀌는지
- 상태 줄이 6-3의 표대로 바뀌는지: 수신함 탭을 닫고 3분 뒤 감지가 빨강, 키를 바꾼 직후 번역이 "키 확인 필요", Webhook을 바꾼 직후 점검표 5단계가 미완료
- 설정 화면을 열어 둔 동안 DeepL과 Slack으로 주기적인 요청이 나가지 않는지(네트워크 요청으로 확인)
- "빠른 메시지 버튼 사용" 스위치를 끄면 수신함의 버튼이 새로고침 없이 사라지는지
- 빠른 메시지의 추가, 수정, 삭제, 순서 변경, 가져오기, 내보내기가 기존과 같은 결과를 내는지(기존 JSON 파일을 그대로 가져올 수 있어야 한다)
- 기존에 저장된 설정이 화면 개편 후에도 그대로 유지되는지

## 10. 구현 순서

1. 9장 V1~V12를 실제 화면에서 확인. 결과에 따라 3-6의 보정 방식과 5장의 창 위치를 정한다
2. 대화별 언어 저장 형식 변경(4-4). 테스트를 먼저 쓰고, lib와 service worker, 메시지 규약을 바꾼다. 화면은 아직 그대로 두고 기존 언어 버튼이 새 형식으로 동작하게 한다
3. service worker 쪽 작업(7장): 권한 확인, 상태 값, 설정 메뉴 열기
4. 말풍선 액션 줄과 번역 상자(3장). 기존 떠 있는 도구 모음 삭제
5. 입력창 위 도구 막대와 번역 스위치(4장). 막대 없음 규칙 포함
6. 빠른 메시지 목록 창(5장)
7. 설정 화면 개편(6장). 기존 저장 값의 구조는 바꾸지 않는다(추가되는 것은 7-2의 statusInfo뿐)
8. Slack 알림 형식 변경(12장). 다른 항목과 독립적이라 먼저 해도 된다. service worker의 알림 문구 생성 부분과 그 테스트만 바뀐다
9. 9장과 12-7의 검증 항목 전체 확인

4~6은 수신함 화면, 7은 설정 화면이라 서로 영향이 없다. 7을 먼저 해도 된다. 2와 3은 양쪽이 모두 쓰므로 먼저 한다.

수정 후에는 확장 프로그램을 다시 로드하고 수신함 탭도 새로고침해야 한다. 탭을 새로고침하지 않으면 예전 화면이 남고 감지가 끊긴다.

## 12. Slack 알림에 미확인 대화 수 표시 (요청 6)

### 12-1. 배지 숫자의 의미 (운영자 확인)

- 수신함 채널 탭의 배지 숫자는 읽지 않은 메시지 수가 아니라 읽지 않은 대화 수다. 한 사람이 메시지를 여러 개 보내도 1이다. 다른 사람이 새로 보내면 2, 3, 4로 늘어난다. 메시지 개수와 관계없이 대화 하나당 1이다.
- 따라서 Slack 알림의 숫자는 모두 "대화" 단위로 적는다. "N건"이라는 표현은 메시지 수로 오해되므로 쓰지 않는다.

### 12-2. 지금 동작과 문제

- 지금 알림의 "새 메시지 1건"은 그 순간 배지가 늘어난 만큼이다. 쌓여 있는 전체 수가 아니다. 다시 알려 주는 기능(리마인드)도 없다.
- 그래서 02:36, 08:46, 09:35에 온 알림 3건이 모두 "1건"으로 표시됐고, 읽지 않은 대화가 3개 쌓였는지 알림만으로는 알 수 없었다.

### 12-3. 바뀌는 알림 형식

```
[Instagram] 새 메시지 · 미확인 대화 3개
수신함의 Instagram 탭에서 확인하세요
미확인 현황: Instagram 3 · WhatsApp 0
감지: 09:35
수신함 열기
```

발신자와 미리보기가 붙는 알림도 같다.

```
[WhatsApp] 새 메시지 · 미확인 대화 2개
보낸 사람: Hong G***
내용: 예약 가능한 시간이 궁금합니다...
미확인 현황: Instagram 3 · WhatsApp 2
감지: 09:41
수신함 열기
```

- 첫 줄의 "미확인 대화 M개"는 그 채널의 현재 배지 숫자다. 읽지 않은 대화가 이번 것 하나뿐이어도 "미확인 대화 1개"로 항상 적는다.
- 한 번에 배지가 2 이상 늘었으면 첫 줄을 "새 메시지 (대화 2개) · 미확인 대화 5개"로 적는다.
- "미확인 현황" 줄에는 두 채널의 현재 배지 숫자를 항상 함께 적는다. 한 채널 알림만 봐도 전체 상황을 알 수 있게 한다.

### 12-4. 숫자의 출처

- 수신함 채널 탭의 배지 숫자("N new") 그대로다. 확장 프로그램이 따로 세지 않는다.
- service worker는 배지 보고를 받을 때마다 두 채널의 최신 값을 이미 갖고 있다(기준 문서 6-1). 알림을 만들 때가 아니라 Slack으로 내보내는 시점의 최신 값을 쓴다. 5초 보류 중에 숫자가 바뀌면 바뀐 값이 나간다.
- 배지가 오르지 않고 목록 변화로만 만든 알림에도 첫 줄과 미확인 현황 줄을 같은 형식으로 넣는다.
- "자리 비운 사이" 알림에도 같은 형식을 적용한다.
- 아직 배지 값을 받지 못한 채널은 숫자 대신 "-"로 적는다.

### 12-5. 대화 수 기준이라서 생기는 동작 (알림이 오는 경우와 오지 않는 경우)

| 상황 | 배지 | Slack 알림 |
|-|-|-|
| 새로운 사람이 메시지를 보냄 | 1 증가 | 온다 |
| 이미 읽은 대화의 고객이 다시 보냄 | 1 증가 | 온다 |
| 읽지 않은 대화의 고객이 메시지를 더 보냄, 그 채널 목록이 화면에 보임 | 그대로 | 온다(목록의 미리보기 변화로 감지). 미확인 대화 수는 그대로 |
| 읽지 않은 대화의 고객이 메시지를 더 보냄, 그 채널 목록이 화면에 없음 | 그대로 | 오지 않는다 |

- 마지막 경우는 알림이 오지 않지만, 그 대화는 이미 미확인으로 알림이 나갔고 미확인 대화 수에 들어 있다. "확인하지 않은 대화가 있다"는 사실은 빠지지 않는다.
- 이 한계는 설정 화면 도움말의 알려진 한계에 적는다: "같은 고객이 이어서 보낸 메시지는, 그 대화를 읽기 전까지 알림이 다시 오지 않을 수 있습니다".
- 다른 기기(휴대폰 앱, 다른 PC)에서 대화를 읽으면 배지가 줄어든다. 미확인 대화 수는 그것까지 반영된 값이다.

### 12-6. 범위 밖

- 일정 시간 확인하지 않으면 다시 알리는 기능(리마인드)은 넣지 않는다. 필요하면 별도로 정한다.

### 12-7. 검증 항목

- 서로 다른 3명이 읽지 않은 채 차례로 보냈을 때 알림 3건이 "미확인 대화 1개", "2개", "3개"로 나가는지
- 중간에 대화를 읽은 뒤 다른 사람이 보냈을 때 숫자가 줄어든 값에서 다시 세어지는지
- 한 채널 알림에 다른 채널의 미확인 대화 수가 올바르게 표시되는지
- 같은 사람이 읽지 않은 대화에 2건을 더 보냈을 때: 그 채널 탭을 보고 있으면 알림이 오고 숫자는 그대로인지, 다른 채널 탭을 보고 있으면 알림이 오지 않는지
