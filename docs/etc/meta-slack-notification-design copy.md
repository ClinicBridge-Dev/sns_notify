# Meta Business Suite → Slack 알림 연동 검토 (v2)

작성일: 2026-11-12 (재검토 반영)
상태: 설계 검토 문서. 구현, 설정 변경, Slack 전송은 하지 않았음.

## v1에서 바뀐 점

1. 페이지를 읽기 전용으로 점검한 결과를 2장에 추가했다. (클릭, 대화 열기 없음)
2. 이 브라우저에서는 Meta 페이지의 알림 권한이 꺼져 있어 OS 알림 방식(B)이 현재 상태로는 동작하지 않는다는 점을 반영했다.
3. 채널 탭의 "N new" 배지를 1차 감지 신호로 추가했다. v1의 "채널별 전용 탭 2개" 구조는 필수가 아니다.
4. 중계 서버를 필수에서 선택 사항으로 낮췄다. 1단계는 확장 프로그램에서 Slack으로 직접 전송한다.
5. 백그라운드 탭 절전 문제와 배지 신호의 한계를 추가했다.

## 1. 목적과 전제

Instagram과 WhatsApp의 새 문의를 놓치지 않도록 Slack으로 알린다. 전체 대화 수집이나 자동 답장은 목적이 아니다.

- 공식 Meta API는 현재 사용할 수 없다.
- Meta Business Suite 탭과 로그인 상태는 유지할 수 있다.
- 발신자 이름/아이디와 짧은 미리보기 정도만 있으면 된다.
- 계정 제한 위험을 낮추는 것이 정보량보다 우선이다.
- 과거 손쉬운 사용 + 확장 프로그램 구현 경험이 있으나, 그 코드는 이번에 확인하지 않았다.

## 2. 플랫폼 구조

### 2-1. 화면 구조

Instagram, WhatsApp 메시지 → Meta Business Suite 통합 수신함 → 채널 탭(All messages / Messenger / Instagram / WhatsApp / 댓글 2종) → 대화 목록 → 선택한 대화 본문

채널 탭 주소:

- 전체: /latest/inbox/all
- Instagram DM: /latest/inbox/instagram_direct
- WhatsApp: /latest/inbox/wec
- Instagram 댓글: /latest/inbox/instagram

### 2-2. 이번에 직접 확인한 사실 (2026-11-12, WhatsApp 탭 기준)

| 항목 | 확인 결과 | 의미 |
|-|-|-|
| 사이트 알림 권한 | 미허용 (묻지 않은 상태) | 이 브라우저에서는 Meta 페이지가 OS 알림을 띄울 수 없다 |
| 서비스 워커, 푸시 구독 | 없음 | 탭이 닫힌 상태의 푸시 알림도 없다 |
| 채널 탭 배지 | WhatsApp 탭을 보는 중에도 All messages, Instagram 탭에 "1 new" 표시 | 한 탭에서 다른 채널의 새 메시지 유무를 알 수 있다 |
| 배지 실시간 갱신 | 세션 초반에는 없던 Instagram DM 배지가 이후 점검에서 나타남 | 새로고침 없이 갱신되는 것으로 보임 (관찰 1회) |
| 대화 목록 | 8개 대화, 스크롤 영역. 항목마다 채널명, 발신자 이름 또는 번호, 미리보기, 시각 표시 | 이름과 미리보기는 목록에서 얻을 수 있다 |
| 대화 식별자 | 목록 행에서 안정적인 대화 ID 속성을 찾지 못함 | 중복 제거는 내용 조합에 의존해야 한다 |

### 2-2-1. 실제 수신 순간 관찰 (2026-11-12 13:59 수신분, WhatsApp 탭을 보던 중)

| 항목 | 관찰 결과 | 의미 |
|-|-|-|
| 채널 배지 | WhatsApp 0 → 1, All messages 1 → 2. Instagram DM 1, Instagram 댓글 1은 그대로 | 배지는 새로고침 없이 오르고, 보고 있는 채널의 배지도 오른다 |
| All messages 숫자 | Instagram DM 1 + WhatsApp 1 = 2. 댓글 1건은 포함되지 않은 것으로 보임 | 채널별 배지를 따로 읽어야 정확하다 |
| 목록 | 새 대화가 맨 위에 추가됨 (8개 → 9개). 이름과 미리보기가 굵게 표시되고 수신 시각이 붙음 | 목록 감지로 발신자와 미리보기를 얻을 수 있다 |
| 미리보기 내용 | 실제 문구 대신 "Message can't be displayed" 안내문이 표시됨 | 수신함이 지원하지 않는 메시지 유형은 내용을 알 수 없다. 이 경우 "내용 미표시, 앱에서 확인"으로 알린다 |
| 읽지 않음 표시 | 화면상 굵은 글씨로 구분됨. 간단한 글꼴 굵기 검사로는 잡히지 않았음 | 굵기에 의존하지 말고 목록 맨 위 항목과 미리보기 변화, 배지 증가를 기준으로 삼는다 |
| OS 알림 | 알림 권한 미허용 상태 그대로 | 이 수신으로 브라우저 알림은 발생할 수 없었다 |

### 2-3. 아직 확인하지 못한 것

- Instagram 목록의 발신자 표기 형식 (아이디인지 표시 이름인지)
- All messages 탭 하나로 두 채널의 미리보기를 모두 볼 수 있는지
- 탭이 백그라운드이거나 오래 방치됐을 때 배지와 목록이 계속 갱신되는지
- 대화가 많아졌을 때 목록이 일부만 렌더링되는지
- 지금 열어 둔 대화에 메시지가 오면 배지가 올라가는지

Instagram 탭은 열지 않았다. 열면 첫 대화가 자동 선택되어 읽음 처리될 수 있기 때문이다.

## 3. 가능한 방법 비교

| 방법 | 현재 가능 여부 | 얻는 정보 | 주요 약점 |
|-|-|-|-|
| A. 공식 API / Webhook | 불가 (전제) | 메시지 단위 전체 | 권한, 온보딩 필요 |
| B. OS 알림 감지 (손쉬운 사용) | 현 상태로는 불가 | 알림에 표시된 내용 | 알림 권한이 꺼져 있고, 켜도 Meta가 채널별로 알림을 보내는지 미확인 |
| C-1. 채널 탭 배지 감지 (확장 프로그램) | 가능 | 채널, 새 메시지 수 | 발신자와 내용 없음 |
| C-2. 대화 목록 감지 (확장 프로그램) | 가능 | 채널, 발신자, 미리보기 | 현재 표시 중인 채널 목록만 대상 |
| D. 자동 대화 열기, 내부 API 호출 | 제외 | 전체 본문 | 정책, 보안 위험 |

### A. 공식 API

Meta가 새 메시지를 서버로 직접 알려주는 공식 경로다. 지금은 쓸 수 없으므로 제외하고, 향후 전환 후보로 둔다.

### B. OS 알림 감지

기존에 쓰던 방식으로 추정된다. 그러나 이 브라우저에서는 Meta 페이지의 알림 권한이 허용되지 않았고 서비스 워커도 없다. 권한을 켜더라도 Meta Business Suite가 Instagram, WhatsApp 수신마다 브라우저 알림을 보내는지는 테스트 전에는 알 수 없다. 또한 확장 프로그램의 알림 API는 자기 알림만 다루므로, 이 방식은 계속 손쉬운 사용 권한을 가진 로컬 앱이 필요하다.

판단: 주 경로로 쓰지 않는다. 기존 구현이 다른 브라우저에서 잘 동작했다면 보조 수단으로만 고려한다.

### C. 페이지 감지 확장 프로그램 (권장 후보)

화면에 이미 표시된 내용의 변화만 관찰한다. 클릭, 스크롤, 내부 통신 가로채기는 하지 않는다. 두 가지 신호를 함께 쓴다.

- C-1 배지: 어느 수신함 탭에서든 모든 채널의 "N new"가 보인다. "놓치지 않기"의 기본 신호다.
- C-2 목록: 현재 표시 중인 채널 목록에서 발신자와 미리보기를 읽는다. 상세 정보 신호다.

정책 측면: Meta는 허가 없는 자동 수집을 제한하고 프로그램 접근에는 공식 API를 쓰라고 안내한다. 화면에 보이는 것만 읽어도 이 조항에서 자유롭다고 할 수는 없다. 다만 Meta 서버에 추가 요청을 만들지 않고 사람의 조작을 흉내 내지 않으므로, 가능한 방법 중에서는 가장 보수적이다.

### D. 자동 조작, 내부 API

목적에 불필요하고 위험만 키우므로 제외한다. 쿠키와 세션 토큰은 어떤 경우에도 수집하지 않는다.

## 4. 권장 구조

### 1단계: 확장 프로그램 단독 (서버 없음)

Meta 수신함 탭 1개 → 확장 프로그램 (배지 + 목록 감지, 대기열) → Slack Incoming Webhook → 비공개 채널

- 탭은 All messages를 우선 후보로 한다. 두 채널 목록이 한 화면에 나오는지 확인되면 탭 하나로 끝난다.
- 그렇지 않으면 Instagram 탭과 WhatsApp 탭을 하나씩 유지한다.
- 미리보기를 읽을 수 없는 채널은 배지만으로 "Instagram 새 메시지 1건" 형태로 알린다.
- Slack Webhook 주소는 확장 프로그램 저장소에 둔다. 이 주소는 비밀값이므로 확장 프로그램을 배포하거나 공유하지 않는 조건에서만 허용한다.

### 2단계: 감지 중단 경고 추가 (선택)

확장 프로그램이 일정 간격으로 외부에 생존 신호를 보내고, 신호가 끊기면 외부에서 Slack으로 경고한다. 작은 서버리스 함수나 기성 생존 감시 서비스로 충분하다.

1단계만으로는 브라우저가 꺼졌을 때 아무 알림도 오지 않아 "문의 없음"과 구분할 수 없다. 놓치지 않는 것이 목적이므로 2단계까지 넣는 것을 권한다.

### 확장 프로그램 동작 규칙

- 권한은 business.facebook.com과 Slack 전송에 필요한 범위로 제한한다.
- 처음 실행하면 현재 배지와 목록을 기준 상태로 저장하고, 기존 대화는 알리지 않는다.
- 화면 변화가 연달아 일어나면 1~2초 모아서 한 번에 판단한다.
- 미리보기가 "You:"로 시작하는 내가 보낸 메시지는 제외한다.
- 로그인 화면이 뜨거나 목록을 찾지 못하면 정상으로 취급하지 않고 Slack에 경고한다.
- 전송 실패한 알림은 저장해 두었다가 재시도한다.

## 5. Slack 메시지 구성

- 채널: Instagram 또는 WhatsApp
- 발신자: 목록에 보이는 이름. 전화번호만 보이면 뒷자리 마스킹
- 미리보기: 최대 80~120자
- 감지 시각
- 해당 채널 수신함 링크

예시: [WhatsApp] 홍길동: 예약 가능한 시간 문의드립니다... (12:41 감지)

첨부 파일은 내려받지 않는다. 고객이 쓴 문구가 Slack에서 멘션이나 링크로 동작하지 않도록 일반 텍스트로 처리한다. 클리닉 상담 내용이므로 비공개 채널과 최소 인원으로 제한한다.

## 6. 누락과 중복

### 누락이 생기는 경우와 대응

| 상황 | 대응 |
|-|-|
| 브라우저 종료, 절전, 탭 닫힘 | 2단계 생존 신호로 경고 |
| 백그라운드 탭이 절전되어 화면 갱신 중단 | 전용 창에 띄워 두고 브라우저의 탭 절전 대상에서 제외. 테스트로 확인 필요 |
| 로그아웃, 세션 만료 | 로그인 화면 감지 후 경고 |
| Meta 화면 구조 변경 | 목록이나 배지를 못 찾으면 경고 |
| 배지 숫자가 그대로인 경우 (읽자마자 다른 메시지 도착) | 목록 미리보기 변화로 보완 |
| 열어 둔 대화에 온 메시지 | 배지가 안 오를 수 있음. 목록 미리보기 변화로 보완 |
| 연속 메시지로 미리보기가 덮임 | 마지막 내용만 전달됨. 알림 목적상 허용 |
| Slack 전송 실패 | 저장 후 재시도 |

### 중복

목록에서 대화 ID를 찾지 못했으므로 채널 + 발신자 + 미리보기 + 표시 시각 조합으로 판단한다. 같은 문구가 반복될 수 있으므로 내용만으로 오래 차단하지 않는다. 헷갈리면 한 번 더 보내는 쪽을 택한다. 놓치는 것보다 중복이 낫다.

## 7. 정책 및 보안 기준

- 대화 자동 열기, 자동 스크롤, 자동 답장, 내부 API 호출 없음
- 주기적 새로고침 없음
- 쿠키, 세션 토큰 수집 없음
- 보안 확인 화면이 뜨면 우회하지 않고 중단 후 알림
- 미리보기는 전송 후 로컬에 오래 보관하지 않음
- 로그에는 본문 대신 상태 정보만 기록

계정 제한 위험이 없다고 보장할 수는 없다. 이 방식은 위험을 0으로 만드는 것이 아니라 가능한 범위에서 가장 낮추는 선택이다.

## 8. 구현 전 검증 항목

구조 확인

1. All messages 탭에 두 채널 대화가 채널 표시와 함께 나오는지
2. Instagram 목록의 발신자 표기 형식
3. 열어 둔 대화에 메시지가 올 때 배지와 목록의 변화

누락 테스트 (테스트 계정으로 실제 발송)

4. 채널별 신규 문의, 기존 대화 추가 메시지
5. 같은 문구 반복, 짧은 간격 연속 메시지
6. 탭을 백그라운드에 30분 이상 둔 뒤 수신
7. 절전 복귀, 네트워크 끊김 복구, 브라우저 재시작 직후
8. 로그아웃 상태에서 경고가 오는지

통과 기준: 보낸 메시지 기록과 Slack 알림을 대조해 누락이 없어야 한다. 6번에서 갱신이 멈추면 전용 창 유지나 절전 제외 설정으로 해결되는지 확인하고, 해결되지 않으면 이 방식만으로는 목적을 충족하지 못한 것으로 판단한다.

## 9. 추진 순서

1. 8장 1~3번 구조 확인
2. 1단계 확장 프로그램 구현, 테스트용 Slack 채널 연결
3. 누락 테스트
4. 2단계 감지 중단 경고 추가
5. 결과와 정책 위험을 놓고 운영 여부 결정
